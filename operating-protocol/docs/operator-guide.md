# TEP-DEMO v0.1.0 운전원 안내서

첫 화면에서 반응기 온도·압력, 세 용기의 액위와 보호·정지 상태를 확인합니다. 정상 범위이며 보호가 활성화된 상태에서 개입과 정지가 없음을 확인하면 다음 온도를 기다립니다. 두 온도 관측으로 이상을 확인한 뒤 냉각수 온도와 실제 유량을 평소와 대조합니다. 입구 온도가 더 높고 유량이 줄지 않은 경우에만 생산량 목표 유지와 감량 승인 요청을 검토합니다. 이 안내서는 TEP Studio Mode 1 폐루프에서 그 판단을 연습하는 해커톤용입니다. 조항을 인용할 때는 `TEP-DEMO@0.1.0/RC-02`처럼 판본과 ID를 함께 기록합니다. [조항 데이터](../data/protocol.json)

## 첫 사건 따라가기

이 예시는 진행자가 카드별 판단을 대조하는 해설입니다. 참가자에게 사건을 낼 때는 아래의 판단 시각별 공개 기준을 따릅니다. 합성 카드 `RC-MAINTAIN-RECOVERY`의 첫 화면을 0분으로 두고 직전 정상 기록과 경보 전후의 계측을 비교합니다. 같은 화면에서 유량 감소·누락, 감량 승인과 거절을 별도 카드로 대조할 수 있습니다. 아래 수치와 승인·인수는 훈련용 입력입니다. [합성 사건 카드](../examples/incident-cards.json)

| 운전원 기록 | 합성 관측 |
| --- | --- |
| 직전 정상(−6분) | 반응기 120.4 °C, 냉각수 입구 35.0 °C, 출구 94.6 °C, 유량 94.0 m³/h. 기존 생산량 목표 22.95 m³/h. |
| 0분 첫 화면 | 반응기 122.7 °C, 압력 2705 kPa(g), 반응기·분리기·스트리퍼 액위 75·50·50%. 0분 상태 기록(`synthetic-run-status`)에서 보호 활성, 비개입과 미정지를 확인합니다. |
| 3분 재확인 | 반응기 123.4 °C, 압력 2718 kPa(g), 반응기·분리기·스트리퍼 액위 75·51·50%, 냉각수 출구 96.0 °C. 3분 상태 기록에서 보호 활성, 비개입과 미정지를 다시 확인합니다. |
| 3분에 추가로 받은 값 | 냉각수 입구 40.0 °C. 같은 시각의 실제 유량 98.0 m³/h를 받은 경우와 유량이 빠진 경우를 각각 따라갑니다. |

1. **0분에 운전·보호 상태를 먼저 확인합니다.** 최신 계기와 0분 상태 기록이 `RC-01`의 보호 조건을 충족하므로 현재 목표를 유지하며 다음 온도 관측을 기다립니다. 3분에는 조건을 다시 확인합니다. 두 온도가 직전 정상보다 각각 2.3 °C, 3.0 °C 높아 `RC-02`로 넘어갑니다. 유량이 빠졌거나 3분 시점 기준 6분 전에 측정한 값만 들어오면 `REQUEST_INFO`를 기록합니다. 첫 요청이 3분이었다면 6분에도 유효값이 없을 때 교대 책임자에게 넘깁니다.
2. **유량을 받으면 조치를 결정합니다.** 평소보다 입구 수온은 5.0 °C, 출구 수온은 1.4 °C 높고, 유량은 4.0 m³/h 많습니다. 이 관측은 유입수가 따뜻해졌다는 설명과 맞습니다. `RC-03`에 따라 기존 목표 22.95 m³/h를 유지하거나, 교대 책임자가 승인한 시각에 감량 목표 19.5075 m³/h를 반영할 수 있습니다. 승인 거절 또는 미확인 상태에서는 기존 목표로 감시합니다. 첫 안내 후 3분 재확인에도 온도 상승이 해소되지 않으면 이관합니다.
3. **복귀 또는 인수를 기록합니다.** 유지 카드에서 6·9·12분의 반응기 온도는 121.2·120.9·120.5 °C입니다. 같은 세 시점에 냉각수 입구 온도 34.0–36.0 °C, 유량 84.6–103.4 m³/h, 정상 압력·액위, 보호 활성·비개입·미정지와 기존 목표 유지를 확인합니다. 12분에 받은 유효한 사건 대장 기록(`synthetic-downstream-incident-register`)은 12분 현재 분리기와 스트리퍼 모두 미결 사건이 없음을 보여 줍니다. 계측과 사건 대장의 확인 시각·출처를 남기고 12분에 `RECOVERED`로 기록합니다. `RC-APPROVED-DERATE` 카드에서는 6분에도 감량 목표가 남아 있고 실제 제품 유량은 21.60 m³/h입니다. 두 값을 `RC-04`에 따라 인계합니다. 6분에는 수락을 기다리는 `OPEN`, 교대 책임자가 수락한 7분에는 `HANDOFF_ACCEPTED`입니다.

`RC-REDUCED-FLOW` 카드에서는 3분의 냉각수 입구가 40.0 °C로 높지만, 유효한 유량은 평소 94.0에서 70.0 m³/h로 줄었습니다. 목표를 바꾸지 않고 `RC-02`에서 `RC-04`로 바로 이관합니다. 상태는 `ESCALATE`를 기록한 뒤에도 인수 수락 전까지 `OPEN`입니다.

`RC-NO-DERATE-APPROVAL` 카드에서는 3분에 승인 없이 기존 목표로 감시를 시작하고, 6분에 거절과 반응기 온도 123.9 °C를 확인합니다. 목표를 유지하며 책임자에게 넘기고, 인수 수락을 확인할 때까지 `OPEN`으로 기록합니다.

`RC-PROTECTION-DISABLED` 카드에서는 3분에 감량 승인과 보호 비활성 기록을 받습니다. 기존 목표 22.95 m³/h를 유지하고 `RC-01`에서 `RC-04`로 즉시 이관합니다. 수락 전에는 `ESCALATE`와 `OPEN`을 기록합니다.

## RC-01 · 첫 화면과 보호 확인

절차집 판본, Mode 1 폐루프, 시뮬레이터 판본을 대조합니다. 기준 시뮬레이터는 TEP Studio `852f0c69ab974540750d61bd1dbfafd56bfd80bb`입니다. **첫 화면부터** 최근 3분의 유효한 아래 계기가 정상 범위에 있는지 확인합니다. 시각과 출처가 있는 유효한 상태 기록에서 보호가 켜져 있고(`enabled=true`), 개입하지 않았으며(`override_active=false`), 운전이 정지되지 않았는지(`terminated=false`) 각각 확인합니다. 후속 판단과 승인된 조치 직전에도 다시 확인합니다.

| 확인할 계기 | 원논문 표 6의 정상 운전 범위 |
| --- | --- |
| 반응기 온도 `XMEAS(9)` | 상한 150 °C |
| 반응기 압력 `XMEAS(7)` | 상한 2895 kPa(g) |
| 반응기 액위 `XMEAS(8)` | 50–100% |
| 분리기 액위 `XMEAS(12)` · 스트리퍼 액위 `XMEAS(15)` | 각각 30–100% |

보호가 꺼져 있거나 개입·정지가 발생했거나, 정상 범위를 벗어났거나, 최신 핵심 계기와 보호·정지 상태 중 하나라도 확인할 수 없으면 **현재 목표를 그대로 두고 즉시 `RC-04`로 이관**합니다. `ESCALATE`를 기록하고 수락 전까지 사건은 `OPEN`입니다. 두 번째 온도 관측이나 검색 결과를 기다리는 것보다 이 판단이 우선합니다. ## RC-02 · 냉각수 추가 계측

계측 담당자에게 반응기 냉각수 입구 온도 `XMEASADD(5)`(°C)와 실제 유량 `XMEASADD(6)`(m³/h)을 요청합니다. 기본 화면의 출구 온도까지 판단 시각을 포함한 같은 3분 관측 구간의 유효값으로 대조합니다. 사건에는 계기 태그, 값, 단위, 실제 계측 시각, 품질, 출처를 남깁니다. 밸브 명령은 명령값으로 별도 기록합니다. 훈련에서는 추가 계측 카드로 값을 받습니다. 모의 운전에 연동할 때는 기본 계측과 함께 `AdvanceResult.additional_measurements`를 전달해야 합니다. [Studio 추가 계측과 단위](https://github.com/khalidlabs/tep-studio/blob/852f0c69ab974540750d61bd1dbfafd56bfd80bb/src/tep_studio/simulation/schema.py#L520-L528) · [계측 출력 구조](https://github.com/khalidlabs/tep-studio/blob/852f0c69ab974540750d61bd1dbfafd56bfd80bb/src/tep_studio/simulation/core.py#L201-L221)

- 유효한 계측이나 평소 기준값이 비어 있으면 `REQUEST_INFO`와 요청 항목을 기록합니다. 첫 요청부터 3분 안에 확보한 값을 평소 기록과 대조합니다. 기한까지 확인되지 않으면 마지막 유효값과 누락 사유를 `RC-04`에 따라 인계합니다.
- 유효 계측에서 입구 온도가 평소보다 높고 실제 유량이 줄지 않았을 때 `RC-03`으로 넘어갑니다.
- 유효한 값에서 입구 온도 상승이 확인되지 않거나 실제 유량이 줄었거나 계측 근거가 서로 충돌하면 현재 목표와 미결 사유를 `RC-04`에 따라 즉시 인계합니다. 그 사이 보호가 개입하거나 정상 범위를 벗어난 경우에도 즉시 이관합니다.

## RC-03 · 기존 목표 유지 또는 승인 후 감량

`RC-01`의 정상 운전 범위와 보호 조건에 맞고 `RC-02`에서 입구 온도 상승과 유량 유지 또는 증가를 확인했으면 `PROVIDE_SOP`와 적용 조항 키를 남깁니다. 현재 설정에서 읽은 기존 생산량 목표를 `Q0`로 기록합니다.

| 운전원의 판단 | 조치와 기록 |
| --- | --- |
| `Q0` 유지 | 기존 생산량 목표와 보호 설정을 유지합니다. 3분 뒤 온도·압력·세 용기의 액위, 냉각수 두 값과 시각이 있는 보호·정지 기록을 다시 확인합니다. |
| 감량 승인 요청 | 교대 책임자에게 관측값과 `0.85 × Q0` m³/h의 훈련 목표, 적용 시각을 전달합니다. 책임자가 목표와 시각을 승인하고 `RC-01`과 `RC-02` 조건이 계속 충족되면, 운전원이 `production_rate` 예약의 값·단위·시각을 승인 기록과 대조해 예약합니다. |
| 승인 거절 또는 미확인 | 변경 권한이 없으므로 기존 목표로 감시합니다. 첫 안내 후 3분 재확인에도 온도 상승이 남으면 거절·대기 사유와 현 목표를 책임자에게 인계합니다. |

승인 후에도 조치 직전의 `RC-01` 조건을 확인합니다. 보호가 꺼져 있거나 상태가 미확인인 경우 그 시점의 목표를 변경하지 않고 `RC-04`로 즉시 이관합니다. 승인 기록에는 조항 키와 승인자, 승인 시각, 적용할 목표의 값·단위·시각을 남깁니다. Studio의 제어기는 생산량 목표를 점진적으로 반영하므로 설정한 목표와 스트리퍼 하부에서 측정한 실제 제품 유량 `XMEAS(17)`을 구별해 기록합니다. **15%는 비교용 훈련 값**입니다. 원논문 표 7은 질량유량 기준의 생산량 변경 시험을 제시합니다. 데모는 Studio가 사용하는 체적유량 단위의 목표에 같은 비율을 적용합니다. ## RC-04 · 정상 복귀 확인과 담당자 인수

**정상 복귀.** 기존 생산량 목표에서 3분 간격의 연속 세 표본을 확인합니다. 세 시점 모두 반응기 온도와 냉각수 입구 온도는 각각 직전 정상값의 ±1 °C, 냉각수 실제 유량은 직전 정상값의 ±10%에 들어와야 합니다. 각 시점의 압력·세 용기 액위가 정상 범위이며, 유효한 상태 기록으로 보호 활성·비개입·미정지를 확인해야 합니다. 판단 시각까지 받은 유효한 사건 대장 조회로 그 시각에 분리기·스트리퍼의 미결 사건이 없음을 확인합니다. 조건을 모두 충족하면 `RECOVERED`와 판단 시각, 사용한 계측과 목표, 대장 조회 참조와 조항 판본을 기록합니다. 복귀용 계측이 빠지거나 훈련 기준을 벗어나면 연속 횟수를 다시 셉니다. `RC-01`의 즉시 이관 사유가 확인되는 시점에는 아래 인수 절차로 넘어갑니다.

**담당자 인수.** 보호 비활성·개입·정지, 정상 운전 범위 이탈 또는 최신 핵심 계기나 상태를 확인할 수 없는 경우에는 현 목표로 즉시 `ESCALATE`합니다. 첫 `PROVIDE_SOP`부터 15분 안에 복귀를 확인하지 못하거나 조치 후 재확인 때 감량 목표가 유지 중인 경우에도 교대 책임자에게 인계합니다. 사건 ID, 적용 조항과 판본, 현 목표와 실제 유량, 마지막 유효 관측, 누락 정보, 승인 결과, 정지·보호 상태, 미결 후속 설비를 전달합니다. 운전원은 교대 책임자의 인수 수락을 확인할 때까지 `OPEN`을 유지합니다. 인수자와 수락 시각이 확인되면 `HANDOFF_ACCEPTED`로 기록합니다. 감량 목표를 되돌릴 때는 별도 승인 기록으로 이어갑니다.

## 분리기와 스트리퍼의 후속 관측

분리기 하부 액체가 스트리퍼로 들어갑니다. `XMEAS(14)`는 이 연결 유량이고, `XMEAS(17)`은 스트리퍼 하부의 제품 유량입니다. 반응기 조치 뒤에는 분리기와 스트리퍼의 액위 추세와 연결 유량을 함께 봅니다. 아래 조항을 고를 때는 최근 4분 동안 분리기 액위와 스트리퍼 온도를 읽은 시각에 맞춰 유효한 유량 세 점을 대조합니다. [Downs와 Vogel, 공정도와 설명](https://users.abo.fi/khaggblo/RS/Downs.pdf#page=2) · [Studio 표준 계기 정의](https://github.com/khalidlabs/tep-studio/blob/852f0c69ab974540750d61bd1dbfafd56bfd80bb/src/tep_studio/simulation/schema.py#L407-L426)

| 먼저 보이는 상태 | 확인과 조항 |
| --- | --- |
| 유효한 유량 세 점이 부족하거나, 변동 폭이 0.2 m³/h를 넘지만 연속 하락하지 않음 | `REQUEST_INFO`로 같은 구간의 `XMEAS(14)`(m³/h)와 시각·품질을 다시 확인합니다. |
| 스트리퍼 온도가 내려가고 연결 유량이 안정 범위에 있음 | 최근 4분의 유효한 유량 세 점에서 최댓값과 최솟값의 차이가 **0.2 m³/h 이하**이면 안정 기준을 먼저 적용합니다. `STR-01`에서 증기 유량 `XMEAS(19)`(kg/h)을 확인하며 분리기 이상은 별도로 추적합니다. |
| 분리기 액위가 오르고 스트리퍼 온도가 내려가며 하부 유출이 안정 범위 밖으로 감소함 | 같은 관측 구간의 유량 세 점이 시각순으로 연속 하락하고 최댓값과 최솟값의 차이가 **0.2 m³/h를 초과**할 때 `SEP-01`을 적용합니다. 분리기 액위 `XMEAS(12)`, 하부 유출 `XMEAS(14)`, 스트리퍼 온도 `XMEAS(18)`를 함께 재확인합니다. |

예를 들어 유량이 25.20 → 25.15 → 25.10 m³/h로 소폭 하락하면 변동 폭은 0.10 m³/h입니다. 스트리퍼 온도가 내려가는 경우에는 안정 기준으로 `STR-01`을 확인합니다. 두 조항의 조치는 **계측 확인과 기록**입니다. 추가 유량을 처음 요청한 때부터 3분 내에도 안정이나 연속 하락을 판정할 수 없거나, 첫 조항 안내 후 4분 내에 필요한 관측을 얻지 못하면 인수를 요청합니다. 하부 유출과 스트리퍼 액위가 함께 오르면 분리기 액위가 내려와도 복귀 확인을 보류합니다. 미결 관측과 발생 순서를 책임자에게 전달합니다.

## 사건 진행과 검색 안내

진행자는 각 판단 시각 `t`에 아래 정보만 골라 참가자 화면과 RAG 질의 문맥을 만듭니다. 필요하면 카드 ID와 별개의 중립 번호를 붙입니다.

| 제공할 정보 | 해당 시각에 볼 수 있는 범위 |
| --- | --- |
| 확인된 설비·운전 정보 | 설비, 운전 모드와 제어 방식, 사용 중인 절차·Studio 판본, 당시에 알려진 담당자와 권한 |
| 계측과 기준값 | 실제 계측 시각 `at_min`이 `t` 이하이고, 별도 수신 시각 `available_at_min`이 있으면 그 시각도 `t` 이하인 기록. 태그·단위·품질·출처를 같이 보여 주고, 계측의 유효성은 실제 계측 시각으로 확인합니다. 기준값도 해당 시각까지 제공된 기록을 사용합니다. |
| 보호·목표·연결 설비 상태 | 판단 시각까지 확인한 보호·정지 상태, 생산량 목표, 연결 설비 사건 대장 조회 결과를 보여 줍니다. 사건 대장에는 기준 시각 `as_of_min`, 수신 시각 `available_at_min`, 출처, 품질, 조회 설비와 미결 상태를 표시합니다. 기준 시각과 수신 시각이 모두 `t` 이하인 조회를 사용합니다. |
| 승인과 인수 | 요청은 `requested_at_min`부터, 승인·거절 결과는 `resolved_at_min`부터 보여 줍니다. 그전에는 요청을 대기로 표시하고 결과와 결과 시각은 진행자 기록에 둡니다. 승인 기록과 인수 수락은 각각 기록 시각 `at_min`과 수락 시각 `accepted_at_min`에 도달하고 당사자가 확인했을 때 보여 줍니다. |

카드 원본의 `case_id`, `title_ko`, `operator_choice`, 미리 적은 검색 후보, `expected_path`는 진행자 기록에 둡니다. 카드 ID나 결과를 드러내는 대장 조회 ID도 진행자가 보관하고, 인용이 필요하면 별도의 중립 번호를 부여합니다. 이후 관측·승인·인수, 외란 번호와 커널 내부 상태도 현재 판단의 입력 범위 밖입니다. 예를 들어 승인 거절 카드의 3분 화면에는 요청 대기까지만 표시하고 6분에 거절을 보여 줍니다. 7분의 인수 기록은 6분 이관 판단을 마친 뒤 7분에 보여 줍니다.

1. 참가자는 설비, 실제 계측 태그, 절차집 판본, 운전 모드로 검색합니다. 후보의 적용 조건과 조치 권한을 확인해 조항 키와 판단 이유를 남깁니다. `PROVIDE_SOP`는 절차 안내이고 조작 권한은 운전원과 책임자의 승인 기록에서 확인합니다.
2. 적용 판본·모드가 맞는 조항이 없으면 `RETRIEVE_AGAIN`으로 한 번 다시 찾습니다. 정보가 부족하면 무엇이 필요한지 명시해 `REQUEST_INFO`로 기록합니다. 재검색 후에도 조항을 찾지 못하거나, 요청 시간이 지나거나, 조항 간 권한이 충돌하면 `ESCALATE`합니다.
3. 후보 순서를 바꿔 같은 사건을 다시 읽어도 적용 조건과 관측으로 같은 판단을 설명할 수 있어야 합니다. 이관을 요청한 경우 담당자의 수락 기록까지 확인합니다.

`export`는 조항 데이터에서 검색용 파일을 생성합니다. 진행자가 시각별로 고른 증거로 질문을 구성하고, 기대 경로를 사용해 참가자의 판정을 확인합니다. [검색용 조항 JSONL](../corpus/clauses.jsonl) · [내보내기 방법](../README.md#조항-확인과-검색용-내보내기) · [합성 사건 카드](../examples/incident-cards.json)

## 자료 범위

이 저장소의 조항·사건 카드는 TEP 벤치마크를 위한 훈련용 작성물입니다. 공개 원논문에서는 계기·운전 범위·외란을, 고정판 코드에서는 표시되는 계측과 조치 경로를 확인했습니다. Schall의 논문은 검색과 검증 절차의 참고 자료입니다. 연구의 개별 사례 JSON은 저자 요청 자료이며 이번 판본의 근거로 논문 본문을 사용했습니다.
